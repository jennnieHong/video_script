## 주석 작성 원칙

이 프로젝트의 모든 코드(프론트엔드 `.tsx` / 백엔드 `.py`)는 아래 주석 규칙을 따른다.

### 1. 파일 상단 블록 주석
모든 핵심 파일 상단에 다음 내용을 포함한다:
- 파일의 전체 역할 및 주요 기능 목록
- 사용하는 주요 라이브러리 및 이유

### 2. 함수 / 컴포넌트 주석
함수나 컴포넌트 정의 위에 다음을 명시한다:
- 역할 (한 줄 요약)
- `@param` 파라미터 설명
- `@returns` 반환값 설명 (해당하는 경우)
- 주의사항, 사이드이펙트, 비동기 여부

### 3. 인라인 주석
다음 경우에는 반드시 인라인 주석을 단다:
- 조건 분기의 각 케이스 이유 설명
- 상수/매직넘버의 의미 (예: `600000 // 10분 타임아웃`)
- 기술적 결정의 이유 (예: `// data URI 방식 (Chrome blob 차단 우회)`)
- 외부 API의 특이 동작 대응 (예: `// end를 playerVars에 넣지 않음 → interval로만 제어`)

### 4. State 주석
useState 선언 옆에 해당 상태의 역할과 사용 시점을 한 줄로 설명한다.

### 5. 수정 시 주석 동기화
코드를 수정할 때, 해당 코드 블록의 기존 주석도 반드시 함께 업데이트한다.
- 구버전 동작을 설명하는 주석은 즉시 제거하거나 수정
- "왜 이렇게 바꿨는지"의 이유가 있다면 주석으로 명시

### 6. 언어
주석은 한국어로 작성한다 (사용자 언어 일치).
단, 영어 기술 용어(state, hook, API 등)는 영어 그대로 사용한다.
